# KRM-IF Metadata Contract — Draft 0.6

Status: logical metadata extension for FastGen temporal tracking. Physical KRM-IF remains prototype v0.2.

## 1. Base provenance

The Base produced by the Draft 0.6 FastGen bridge is generated by the local KASF05_Reader OLA equation and `KRM-PROTO-PCM-Q-v1`. `canonical_kasf_export` remains `false`.

The bridge records, where available:

- Source, KASF, Base SHA-256 and PCM domain geometry;
- Generator and local Reader identifiers;
- normalization policy and PCM quantizer profile;
- symmetric edge-guard crop and alignment declaration;
- temporal tracking enabled/disabled state;
- `temporal_tracker_assignment`: `greedy` or `hungarian`;
- `temporal_track_map_sha256`, identifying the diagnostic JSONL sidecar;
- `temporal_tracking_payload_modified`, which remains false unless the separate experimental refinement flag is enabled.

Track-map metadata is provenance and analysis context. It is not needed to reconstruct Base or Raw Residual and cannot be used to modify the authoritative residual payload.

## 2. Exact reconstruction

For integer Source PCM `X` and the recorded integer Base PCM `B`:

```text
R = X - B
X = B + R
```

The Raw Residual is authoritative for exact restoration. Source/Base SNR measures how well the encoder Base approximates Source; it is not the exact-restoration metric. A low Source/Base SNR means more information is carried by Raw Residual, not that reconstruction has lost information.

## 3. Tracking metadata vs audio payload

Greedy and Hungarian track association update only the JSONL track map. With the same input and generator settings, both assignment modes must produce byte-identical KASF and Base outputs. This invariant is covered by tests and by the real-audio comparison report.

`--experimental-track-refine` is separate: it can change component frequency and phase and therefore can change Base and Raw Residual. It must remain marked experimental and opt-in.
